- [Security] Fix command and template injection in `tutor local/dev/k8s do` jobs. Job arguments, such as the user name and password of `do createuser`, were included verbatim in job scripts. Because these scripts are rendered as Jinja2 templates on the host and then run by the shell in a container, a crafted argument could run arbitrary code on the host, or in the container. Arguments are now always passed as plain values to the shell, Python and SQL commands of the `createuser`, `importdemocourse`, `importdemolibraries`, `print-edx-platform-setting`, `settheme`, `sqlshell`, `convert-mysql-utf8mb4-charset`, `update-mysql-authentication-plugin` and `tests` jobs. As a consequence, `do print-edx-platform-setting` now only accepts the name of a setting, and not an arbitrary Python expression. Plugin developers who implement their own `do` jobs should escape untrusted values with the new `tutor.env.escape_template` function, as documented in the `CLI_DO_COMMANDS` filter. (by @Abdul-Muqadim-Arbisoft)
